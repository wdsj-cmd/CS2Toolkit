# CS2Toolkit

一个面向 `Counter-Strike 2` 的 Windows 桌面工具，提供游戏资源替换、GSI 实时事件联动、创意音乐盒、视觉覆盖和 `GO桌宠` 等功能。

## 项目状态

- 技术栈：`Python`、`PySide6`、`PySide6-Fluent-Widgets`
- 当前平台：`Windows 10/11`
- 主要依赖：`PySide6`、`PySide6-Fluent-Widgets`、`requests`、`pycaw`
- 开源许可证：`GPL-3.0-only`

## 功能概览

### 资源替换
- 自定义开屏动画，支持 `WEBM`
- 自定义启动音效
- 自定义游戏字体
- 预设保存、切换、删除与导入导出

### GSI 联动
- 基于 `Game State Integration` 监听游戏状态
- 根据击杀、死亡、炸弹、回合状态等事件播放音效
- 支持更细粒度的互动事件配置

### 创意音乐盒

从左侧导航栏进入 **“创意音乐盒”**，为游戏中的不同阶段配置自己的音乐切片，组合出一套自定义音乐盒。

| 场景 | 支持的音乐事件 |
| --- | --- |
| 大厅与选队 | 主菜单、选择队伍（首次进入地图选队，或按 `M` 打开队伍菜单） |
| 回合流程 | 准备阶段、回合开始、回合剩余十秒 |
| C4 安放 | C4 已安放 |
| C4 十秒警告 | 通用、自己安放、其他人安放，可分别配置 |
| 回合结果 | 回合胜利、回合失败 |
| 个人事件 | 获得 MVP、玩家死亡 |

播放设置：

- **切片编辑**：设置起始位置、播放时长、切片音量和循环；播放时长设为 `0` 时，播放从起始位置到音频结尾的完整剩余内容。
- **独立随机开关**：每个事件都可选择随机播放或固定播放选中的切片。开启随机后，每次触发和循环换片时重新抽取，有多个不同切片时避免连续重复。
- **完整播放后切换**：回合胜利、回合失败和 MVP 各有独立开关，默认关闭。开启后按设置时长完整播放一次，再切换后续事件；手动停止和试听仍立即生效。
- **独立音量与试听**：支持音乐盒总音量和各切片音量调节，可在进入游戏前试听。
- **音乐包管理**：支持创建、重命名和切换多个音乐盒，通过 ZIP 导入导出音频与事件设置。支持 `MP3`、`WAV`、`FLAC`、`OGG` 等音频格式。

使用方法：

1. 首次使用时，在设置中重新生成 **GSI 配置**，然后重启 CS2。
2. 打开 **“创意音乐盒”**，点击 **“新建”**，或通过 **“导入 ZIP”** 导入已有音乐包。
3. 点击事件旁的 **“设置”**，添加音频并调整切片参数、随机播放等选项，点击 **“保存切片”**。
4. 打开 **“启用创意音乐盒”**，进入地图测试；可通过 **“导出”** 分享整套音乐包。
5. 若与游戏原音乐重叠，可在 CS2 中调低对应事件的原音乐音量。

计时与识别：优先使用游戏数据中的实际倒计时；缺失时，在准备阶段结束后读取顶部计时器，同步后使用本地倒计时，并在切回游戏前台时重新校正。计时信息不可用时，不按固定回合时长触发十秒音乐。C4 图标识别用于辅助提前触发安包音乐，无法确认安包者时使用通用十秒切片。

### 游戏内视觉
- 自定义闪光替换图
- 自定义击杀图标
- 自定义死亡媒体
- 支持文件夹资源随机选择

### GO桌宠
- 支持图片、GIF、`WEBM`
- 支持大小与位置调节
- 支持游戏内显示和主播输出窗口模式
- 支持根据血量、炸弹、胜负、MVP、Freeze Time 等事件切换状态

## 快速开始

### 环境要求
- 已安装 `Python 3.10+`
- 已安装 `Counter-Strike 2`
- 操作系统为 `Windows 10/11`

### 安装依赖

```bash
pip install -r requirements.txt
```

### 运行项目

```bash
python main.py
```

### 自定义数据存储目录

默认情况下，CS2Toolkit 会将您的配置文件、导入的媒体素材等保存在系统 C 盘 (`%LOCALAPPDATA%\CS2Toolkit`)。如果您希望将其移动到其他盘符：

1. 打开软件，进入 **“设置”** 页面。
2. 找到 **“数据存储”** 面板，点击 **“迁移目录”**。
3. 选择新的目标文件夹（例如 `D:\CS2ToolkitData`），软件会自动将所有配置和素材安全复制过去。
4. 迁移成功后软件将退出，重新启动即可在新路径下运行。

## 私有更新源注入

仓库默认不写入正式的公告源和版本检测地址。

- `app/release_endpoints.py` 中保留的是公开仓库可提交的占位符
- 本地正式打包时，可通过私有配置文件或环境变量注入真实地址
- 打包完成后，`build.py` 会自动将源码恢复为占位符，避免误提交真实链接

推荐方式：

1. 复制 `release_endpoints.local.example.json`
2. 重命名为 `release_endpoints.local.json`
3. 按你的实际地址填写：

```json
{
  "update_url": "example.com/version.json",
  "announcement_url": "example.com/announcement.json"
}
```
